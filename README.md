# 期末專題看板

中興大學 生物產業管理研究所（生管學程）1151 學期「量化研究法（上）」期末資料分析專題看板，授課教師：王思永。

一頁看完所有組別的研究題目、資料、研究方法與進度；同學掃 QR、免登入，選自己的名字就能更新組卡、在別組下面留言建議。老師用 PIN 進入老師模式，留言以橘色標示。

線上網址：https://halcyone1234-ux.github.io/final-board/

## 內容

- **規範區塊**：分組 2～3 人、資料 ≥ 1,000 筆、30 分鐘報告＋10 分鐘 QA、簡報必須涵蓋的七個步驟（對照 W08 簡報 p.66–67）。
- **總覽表**：每組一列：題目、資料與筆數、方法、七步驟完成度、進度（倒數 6 週 → 1 週）、留言數。
- **組卡**：起手式六格表（故事、Y、X、Z／M／W、資料結構、四張臉）＋七步驟：研究問題與假設 → 文獻 → 研究設計 → 測量（信度・效度）→ 抽樣與資料蒐集 → 敘述統計與視覺化 → 分析與推論。
- **留言**：每組下方；自己的留言可刪，老師可刪任何留言。
- **組徽**：10 隻像素小動物（`icons.js`），各組在「編輯組卡」挑一隻，每組一隻、先選先贏。
- **投影模式**（網址加 `#board`）：一個畫面看全部組別：組徽、題目、資料筆數、方法、七步驟、進度、最新留言，外加一格 QR。
- **老師模式**（網址加 `#admin`，或頁尾「老師模式」，PIN 見 `firebase-config.js`）：以老師身分留言、修改組名與成員、開投影模式、顯示 QR。

網址加 `?c=代碼`（例如 `?c=1152-final`）可開一個全新的班級資料。新班的預設組別寫在 `app.js` 的 `DEFAULT_GROUPS`，第一次打開時自動建立（已存在的組不會被覆蓋）。

## 安裝

沿用星座問卷的 Firebase 專案 `zodiac-af366`，資料放在 `board/<班級代碼>`。

1. Firebase 主控台 → Realtime Database → 規則：把 `database.rules.json` 裡的 `"board": {…}` 區塊**加進現有規則**（與 `classes`、`quiz`、`consent` 同一層，不要整份覆蓋），發布。
2. GitHub Pages：Settings → Pages → main 分支根目錄。

`firebase-config.js` 的 apiKey 還是 `YOUR_…`，或網址加 `?mock=1` 時，網站改用「本機測試模式」：資料只存在這台瀏覽器的 localStorage，同一台電腦的分頁互相同步。

## 技術

- 純靜態：`index.html`、`style.css`、`app.js`（畫面）、`data.js`（Firebase／mock 資料層），無建置步驟。
- CDN：Firebase JS SDK 10.12（compat）、qrcodejs 1.0.0。
- 身分：每支手機自動產生匿名碼存在 localStorage；同學從名單選自己的名字。留言帶匿名碼，只有同一支手機（或老師）看得到刪除鍵。
- 安全：規則開放讀取；組卡可改不可刪、須保留組名與成員；留言可新增、可刪除、不可改內容。PIN 與刪除權限只在前端把關，適合課堂規模。
